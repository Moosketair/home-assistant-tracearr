## Risques et points à qualifier

- **Réseau.** Le polling REST ne tient pas compte du `Retry-After` (contrairement à la boucle SSE) ; pas de plafond explicite sur l’établissement de connexion SSE (`sock_read=80`, `total=None`), ni sur le cumul de lignes `data:` d’une trame. Un JSON REST illisible lève une erreur de décodage hors `TracearrError` ; `data`, `meta`, `accounts`, débit et progression ne sont pas tous validés avant usage. Un objet sans `data` est assimilé à une liste vide. Tester timeout en connexion/en lecture, EOF, 3xx, JSON invalide, pagination et 429 avant de choisir la stratégie.
- **Connexions et nettoyage.** `start()` n’est pas idempotent : un second appel écraserait les deux handles ; le chemin de setup normal ne l’appelle qu’une fois. Plusieurs URLs désignant la même instance peuvent aussi créer plusieurs entrées. Aucune preuve de double SSE en usage normal. En JS la promesse de souscription vérifie connexion et `_closed`, mais pas une génération de montage ; une résolution tardive après remontage immédiat sur la même connexion mérite un test. Après rejet de `subscribeMessage`, `_connection` reste renseignée. Vérifier rechargement, changement de connexion et teardown pendant une requête ou une animation.
- **Coût.** À chaque événement utile : calcul des stats sur toutes les sessions, deux parcours de découverte serveur, comptage des sessions pour chaque capteur serveur ; chaque abonné WS reconstruit toutes les entrées. Dans la carte : tri, `JSON.stringify`, `find` serveur par session, calcul des couleurs ; avec badges HA, le setter `hass` recalcule l’en-tête même pour une entité non liée. Chaque carte montée a son tick 250 ms, y compris vide/masquée ; plusieurs recherches DOM par session, création d’`Intl.DateTimeFormat` si heure de fin. L’autoplay évite un déplacement en arrière-plan, pas le réveil du timer. Une métadonnée qui change peut reconstruire toute la liste. Aucune mesure FPS/CPU, mémoire backend ou coût GPU du flou : profiler avant refonte.
- **Confidentialité.** Aucune utilisation explicite de la clé de config dans le payload WS ou les messages de log examinés. En revanche chaque client WS authentifié reçoit toutes les sessions (utilisateurs, appareils, titres, URLs d’images) et les options de toutes les entrées ; les filtres de carte ne sont pas des droits d’accès. Pas de liste blanche des champs de session. Clé conservée dans la config entry ; URL HTTP acceptée ; champ du token déclaré `str`, pas de sélecteur de mot de passe explicite. Les avatars personnalisés peuvent être chargés sur un tiers via HTTP(S) ; confidentialité des dashboards partagés et politique d’accès à valider. Ne pas interpréter cela comme une fuite de clé observée.
- **Données et identités.** Compteurs frontend/backend du direct ne suivent pas tout à fait la même règle pour une décision non reconnue et une décision `copy` (JS 66–72 vs `model.py:7–23`). Tri `sort: server` suppose `server_name` non nul. Les appareils HA par serveur partagent `(DOMAIN,server_id)` entre entrées ; le set `known` ne rétrécit pas avant reload. Les champs de formulaire par libellés peuvent se télescoper si deux serveurs portent le même nom. Le sélecteur de carte retombe sur la première entrée même si un `entry_id` explicite a disparu. Importance sur données réelles non mesurée.
- **Ergonomie/maintenance.** L’éditeur conserve les sections ouvertes mais reconstruit son DOM ; les options de source sont un instantané `get`, pas un abonnement. À vérifier au clavier : focus, liste de nouveaux flux et sélection d’entité. `show_name` hérite par valeur alors que `only_positive`/`blink_positive` combinent réglage global et local par OU. Vérifier l’intention des surcharges. Le fond cinéma est sombre mais le texte hérite du thème ; lisibilité à mesurer en thème clair. Le JS (1 598 lignes) rassemble calcul, CSS, HTML et éditeur ; éviter de le scinder avant des tests de contrat sur le module publié.
- **Traductions.** Parité de **60 chemins de texte** et de leurs placeholders vérifiée entre `strings.json`, `en.json`, `fr.json`. Le test du dépôt contrôle seulement la syntaxe des accolades. Ni les libellés dynamiques français du flow ni les noms anglais des entités ni le JS en français ne sont localisés par ces JSON. C’est une limite de couverture linguistique, pas une erreur de chargement constatée.
